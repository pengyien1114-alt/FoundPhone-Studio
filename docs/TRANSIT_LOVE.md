# 換乘戀愛：二十一天錄製流程

沿用原 FoundPhone 手機、鎖屏、桌面與 49 個 App。密碼 **0112**，故事來源為 `stories/template/story.json`（revision 7）。本次內容更新保持相容存檔，不重設本輪進度。

入口為備忘錄的逐題入住資料，填完再讀錄製須知。X 保留官方文字紀錄與日常動態；KKT 是節目組的逐題作答及限時正式聊天室；Safari 按集整理 theqoo 公開討論。需要開啟哪個 App，就由該 App 的圖示發通知；鎖屏通知會在解鎖後開啟對應 App，橫幅直接開啟來源 App。

## 節目時間與資訊公開

- 第 0 天：超過 300 字的事前見面紀錄，接著在 KKT 依序完成 Q1、Q2、依背景設定的 Q3；確認後才入住。
- 第 1 天：五男五女只公開姓名與 MBTI，備菜與洗碗分工；本人朗讀至少 200 字的介紹信、分享感受、選擇是否拆禮物。角色卡的自寫介紹信已由故事資料完成並封存。
- 第 2 天：女生邀請非前任的當日在場男性，重複邀請反選與合規補配；只通知當事人。限時匿名聊天室不顯示頭像或姓名，禁止詢問身分資訊，出發前關閉。八點前返屋，夜間領取隔天任務卡。
- 第 3 天：接受指定配對與正式任務環節，選擇任務完成方式後開放後續活動，五點前返回。晚餐後一位新女嘉賓加入。
- 第 7 天：回憶房間意願、討論與人選確認；必要時安排不公開配對的正式談話。依本次作者確認，**第七天晚餐後**公開年齡與職業（採用每日流程，取代舊總則的第八天），仍不公開前任。
- 第 10 天：匿名禮物抽選與互選、剩餘名額補抽，未配對的一位女嘉賓與新男嘉賓約會；八點前返回後正式介紹。
- 第 13 天：雙向互選成功才約會，否則留屋；旅行搭檔另行選擇與配對，不沿用短信投票。
- 第 14 天：三男三女分組乘機、與搭檔安排行程、下午四點前集合。全員抵達並確認觀看影片後，才公開六對過去關係與事前素材。
- 第 21 天：完成兩次不能跳過的正式線上談話回答、當日短信與後訪，最後選擇重新理解過去、走向指定的新對象、或保持單身；先閱讀回顧再確認結束。

其他天安排有界線的共同生活、分工與面對面互動；具體小事由本輪種子選取，不以第三人稱披露未觀察到的私下行動。設定中的延後入場人選仍固定保存，但錄製旁白、公開名單與預告不提前列出人選或登場時程。

## 玩家作答與匿名短信

所有互動一題一題進行，不提供自由文字輸入。入住姓名由玩家自行輸入；其餘劇情回答維持選項。KKT 保留原有畫面，點下方唯讀訊息欄才開啟選項浮層；點選後直接發出自己的回答，取消不作答。採訪、匿名聊天室、短信與動作都使用同一個入口；未送出的下一題不會提前出現。

每晚先選當日在場異性，再從三組一至兩句的已寫好短信中選擇。送出時產生並固定本輪全體投票，當晚只能提交一次。先讀匿名收件（零封明確顯示「沒有嘉賓選擇您」），才解鎖 X 是否選擇你的提示；第十四天之後改為前任當晚的收件人姓名，內容仍不公開。NPC 有對其他嘉賓的偏好，不因玩家寄出短信或白天配對就強制互選。

第一天新增落座、完整到場介紹、三人分房、備菜分歧、飯桌接話及晚間單獨相處。所有出場姓名由實際在場名單產生，男嘉賓無照片。每個選擇後都有不同回應；選定對象後的對話在 X 顯示，theqoo 同集討論追加已發生的片段。

每天從實際在場名單安排共同生活與角色事件，逐題選擇當下要做的動作或要說的話。`relationships.ts` 從已存答案重算親近、信任、表達清晰度、壓力、實際相處次數與最近相處日，不在重新開 App 時重複加分。不同選項有代價：要求立刻確認可能拉近表面距離，卻降低信任並累積壓力；保持輕鬆能留空間，卻較難讓心意清晰。私下關係數值不直接列在公開頁面。歷史片段只用截至當日的紀錄，後來的選擇不改寫過去。

第七、十四、十九天新增節目組安排的正式談話；第二十一天的必談再次確認。六種分手背景各有具體修復、只想回到過去、先守住界線的選項與不同回應。復合需有持續相處、足夠信任、確實處理原問題，並在最後談話明確同意重新交往；初始復合百分比不等於對方意願。換乘需要對同一個人的實際相處、清楚表達、後期持續靠近，並超過對方對其他嘉賓的意願；臨時改終選名字、只寄短信或反覆施壓均可能不被接受。

約會、旅行搭檔、短信及終選分別計算。第十三天互選以已累積的相處影響對方意願；夜間投票另有當日情緒、原有偏好和先前選擇。終選不再擲隨機結果：同一份存檔得到同一結果，但不同過程可以導致復合成功、復合未獲接受、換乘成功、換乘未獲接受、或主動單身。回顧使用實際選項與寄件紀錄。

X 自動置頂只在沒有正在閱讀的詳情時開啟；解鎖下一篇不會蓋掉當前推文。連續同 App 的新增段落合併到同一篇，完整讀到下一個決策點。

本作是離線故事與規則模擬，不在執行時呼叫在線模型。內容由故事資料與條件投影，不假裝能理解任意自由文字。revision 7 的問題與事件路徑已有變動，因此舊版進度會重開本輪；鎖屏與桌布仍使用作者提供的兩張合照。

## 網頁與離線快取更新

連線時首頁和故事 JSON 使用 Network First，故事請求包含本次建置識別碼並略過瀏覽器 HTTP 快取；離線時回退至已快取的同版資料。新版 Service Worker 接手後會將仍使用舊版的分頁導回原手機入口，不建立另一套介面，不清除 IndexedDB 存檔或桌面設定。回到分頁或恢復連線時也會檢查更新。

快取回歸測試模擬舊 Service Worker 持續返回舊首頁與故事：更新後需能自動載入最新手機、保留相容存檔、讀到同網址更新的故事，且再次離線仍能開啟。瀏覽器測試的故事路由包含版本查詢參數。

## 換日提示與前任互動補強

KKT 收件、X 提示和其他待閱讀的正式訊息，均可從下方訊息欄繼續。第一晚完成兩題後訪後，下方直接顯示「進入第 2 天」，仍由玩家確認才換日，不自動跳過短信或採訪。

六種背景分別編寫初見時的克制、第一晚心結、介紹信、禮物，以及前期／回憶房間之後／公開之後三階段的談話。選擇自己的前任時不再使用新朋友的互動模板；熟悉感與未修復的信任分別計算。背景與先前的行動會改變回應，不把一段坦白直接當作復合。未公開前的論壇不轉述私下談話內容。

此更新保留既有 revision、事件 ID 和當前進度；舊答案仍按原選項識別，新答案另記選項序號。故事改寫可在舊進度繼續體驗，沒有新增需要重開才能到達的節點。

## 論壇、短信與首晚心動判定

每集 theqoo 有自己的集中樓與 20 層開場討論，後續相處、實際收件與集末反應依原解鎖點加入同一串；包含不同立場、引用樓層、玩梗和改觀，不再輪播同一組規則提醒。未公開的談話不在論壇披露寄件人或前任身分。

節目官方 X 的愛心、轉發、觀看與總留言數由故事資料提供，列表與詳情都顯示基礎數值；玩家互動累加，精選留言依片段各自編寫。普通動態仍保留原本規模。

寄給 X 的短信有六種分手背景、三個階段的文案；新對象則依實際座位、備菜、談話或約會提供選項。寄件人仍匿名，收到的短信同樣會呼應已發生的相處，並不讀取尚未收到的當晚寄件內容來反向選人。

第一晚以可觀察的接觸計算注意力：座位、共同備菜、飯桌接話及單獨相處。對話願意彼此聽完時，這段相處的權重大於開場偏好的差異，不再被高於玩家初值的全局隨機分數蓋過；反覆要求立刻表態會降低分數。沒有新增無條件補發或按玩家收件人強制互投。後續仍依持續相處、對方偏好及過往選擇計算。

已儲存的投票不重新抽取。新規則適用尚未發送的夜晚；想重新體驗第一晚的新收件判定，需要新開一輪。其餘角色設定、切段與換日流程保持相容。

## 私人片段、完整約會與接續話題

公開前的事前見面、回憶房間、私下前任談話與相關約會紀錄標記「僅玩家可見」，不展示觀看、愛心、轉發、觀眾留言或回覆輸入欄。論壇也不轉述這些私下談話。一般公開節目片段仍保留大型節目的互動數與精選留言。X 正文加大至 21px，列表 20px，並增加行距，沿用原 App 版型。

第 2、3、10、13 天的正式約會增加現場對話、兩個逐題選項與各自後果。接話、比較追問、保留空間分別影響實際約會對象的親近、信任、清晰度與壓力；一次約會僅計一次相處。第 13 天沒有互選成功時改為留屋活動，不憑空對未約會的人加分。原本的約會後感受提問與後訪保留。第 7 天的秘密見面也補長，接續既有正式修復談話。

每日夜談有不同日常話題；和同一人接續談時不再提供已選過的原句。前任依六種分手背景接續先前談話，再轉入當天的小事；未公開關係的內容仍只供玩家閱讀。已完成的事件、短信投票與答案不重置；新增約會決策出現在尚未讀過的約會之後，已越過該段的存檔不強制回溯。

## 生活事件、口語對話與感情分支

取消固定的晚間「挑一個人聊天／選接話方式」介面，既有 `focus`、`approach` ID 只作存檔相容用途。新互動從 24 段生活事件抽取：前、中、後期各八段，每輪在同階段不重複，刷新不重抽。角色從實際入住名單安排，前面實際寄件、相處會影響下一段有哪些人出現在附近；不把短信對象等同於對方當晚投票，也不讓未入住者提前出場。

每段有具體的動作選擇與不同後果：留下幫忙、一起偷吃、開個玩笑、說出嫉妒、或去陪女嘉賓。第二段依第一個動作展開，選項數不同，不再固定三種「健康溝通／施壓／輕鬆聊」文案。非首日的選項次序由種子決定，較合適的回答不固定在第一格。與女嘉賓待著或自己離開的完整段落不會替男嘉賓加分；有實際互動才記一次相處。坦白與明確界線可以緩和累積壓力，但不抹除先前相處與對方的其他偏好。

六種分手背景各有前、中、後期私人片段，共 18 段，每個階段只觸發一次；後續相處回到不同的當下事件，不重播同一場修復演說。第七、十四、十九天正式見面和最後聊天室也改為較短、直接的對話，保留原本復合需要共同修復及明確承諾的條件。角色有各自的開場方式；公開前的私人內容仍標記僅玩家可見，不進觀眾留言與論壇。

第一晚的備菜、飯桌、介紹信、事前見面，以及日常、後訪、給 X 的短信都調整為較自然的口語。正式約會、每晚短信、年齡職業與 X 的公開日、終選流程保持原路徑。X 回應與 theqoo 追加樓層改為討論實際抽中的事件，短信也可回應當天發生的小事。

保留 revision 7 和既有事件 ID。舊存檔中的姓名選人與已送短信不重算，已進入的舊夜談可接完；尚未開始的下一段使用新事件。新答案分開保存動作文字、實際對象、事件 ID、選項與效果，避免把動作句誤認成人名，也不因反覆開啟 App 重複加分。歷史場景只讀當日以前的資料。

## 桌面、文字版本與開場音樂

X 和 KakaoTalk 放在桌面第一頁。`firstPageApps` 與 `homeLayoutRevision` 讓已保存的桌面也只搬動一次，保留 App、小組件及遊戲進度；之後玩家自行調整的位置不反覆覆蓋。

原備忘錄的入住設定先選「繁體中文／简体中文」，再輸入姓名。選擇獨立保存在 `ui.notes.script`，在同一份備忘錄可隨時切換。使用內附 OpenCC 字詞表轉換故事、對白、選項、論壇與通知的顯示文字，離線可用；人物資料、選項值、事件 ID 和關係效果保持原始值，避免簡繁字形影響判定。既有存檔未選版本時維持原文字，回備忘錄即可補選，毋須重開。

開場音樂仍在第一次觸碰後播放，跨 App 共用一個播放器。播放一遍便停止，後續點擊不會自動重播；可從原音樂 App 手動再次播放。

## 角色支線、約會分歧與後續記憶

修正事前訪問只有同一立場、飯桌問題與答案不相干、以及中性詢問之後替玩家追加責怪等情況。六種分手背景的第三題各自提供對應選項，第一天可明確回答主動、等待或轉開話題，約會後的提問與感受選項一致。

新增封存的 `character-stories` 結構化資料。八位男嘉賓各有前、中、後三段專屬相處，共 24 段，依實際在場人物組合與原有生活事件交替出現。選擇、說話方式與反應使用角色自己的內容。另有八段後期疏遠路徑：沒有足夠實際接觸的新對象會維持一般關係，也可能在與其他女嘉賓靠近，不會突然把玩家當成最重要的人。前任則保留六種過往與八種個性反應。

第 2、3、10、13 天的約會新增 32 組角色情境。實際約會對象決定兩個問題與選項，第一個回答改變後半段互動；同一對象再談到同一件事時，會接回上次實際回答，容許延續或改變立場，已選過的原句不直接重出。選擇的原文、回應與效果保存後不重算。保留每次兩個決策、約會後感受與既有收件流程。沒有互選的第十三天仍走留屋分支，不向不存在的約會對象加分。

八條後續記憶只在玩家確實向該角色說過相應的話、且隔過至少一天後出現；處理過便不重複。對方會接回當時的原句，玩家可延續、澄清或退開。新晚間答案亦保存實際文字和演出結果，將來的選擇不改寫既有片段。

五位固定女嘉賓各有前、中、後期可觀察的生活線與相對穩定的互動對象；與其他嘉賓的熟悉會逐步影響獨立短信偏好，不等同約會或旅行配對。所有內容只寫玩家看見或聽見的事，不透漏未公開的前任身分。另有 21 個共同生活細節供匿名短信引用，同一件事可有不同寄件人的描述，收件不替玩家指定猜測答案。

保留現有事件 ID、出場日期、姓名輸入、簡繁轉換、音樂單次播放、桌面與兩張桌布。已開始的舊約會沿用原問題，尚未開始的場次使用角色版本。故事檔約 4 MB，離線預快取單檔上限調整為 5 MB，確保新增內容仍可離線載入。

存檔中的答案以原始字串作唯讀解析快取；同一份進度在一次呈現中重複讀取不再反覆解析，原始答案變更時會失效。關係效果仍由錄製過程重算，不因快取或重新開 App 增加相處次數。完整劇情測試限制同時使用兩個工作程序，避免大型故事樣本互搶資源。

## 遊玩不中斷與進度備份

背景下載新版不再強制重新導向或跳回鎖屏；新程式與故事於下次正常開啟時載入。Service Worker 只對沒有 `appRelease` 標記的舊快取頁進行一次修復，已進入現代玩家的頁面不會因啟用新版而被導航。

每次選擇先同步保存小型進度備份，再依序寫入 IndexedDB；密集操作只保留最後一份待寫內容，避免舊交易覆蓋新進度。回到背景或頁面關閉時補存，重開選較新的有效記錄。備份不含故事媒體，儲存受限時仍嘗試另一種儲存方式；兩者都失敗才提示。保留現有作品、存檔 ID 與 revision 7。閒置時不再每五秒重新呈現整季劇情，同一狀態的故事投影使用記憶化。

回歸涵蓋新版 Worker 在姓名輸入中啟用而不重載、選項後立即重開且主存檔落後時恢復最新約會答案，以及儲存失敗、備份損壞與連續寫入。瀏覽器測試使用行動 Chromium；實體 iPhone Safari 的系統回收行為仍須真機確認。
