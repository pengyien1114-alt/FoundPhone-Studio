# 換乘戀愛：二十一天錄製流程

沿用原 FoundPhone 手機、鎖屏、桌面與 49 個 App。密碼 **0112**，故事來源為 `stories/template/story.json`（revision 7）。作品更新後重新建立本輪進度。

入口為備忘錄的逐題入住資料，填完再讀錄製須知。X 保留官方文字紀錄與日常動態；KKT 是節目組的逐題作答及限時正式聊天室；Safari 按集整理 theqoo 公開討論。需要開啟哪個 App，就由該 App 的圖示發通知；鎖屏通知會在解鎖後開啟對應 App，橫幅直接開啟來源 App。

## 節目時間與資訊公開

- 第 0 天：超過 300 字的事前見面紀錄，接著在 KKT 依序完成 Q1、Q2、依背景設定的 Q3；確認後才入住。
- 第 1 天：五男五女只公開姓名與 MBTI，備菜與洗碗分工；本人朗讀至少 200 字的介紹信、分享感受、選擇是否拆禮物。角色卡的自寫介紹信已由故事資料完成並封存。
- 第 2 天：女生邀請非前任的當日在場男性，重複邀請反選與合規補配；只通知當事人。限時匿名聊天室不顯示頭像或姓名，禁止詢問身分資訊，出發前關閉。八點前返屋，夜間領取隔天任務卡。
- 第 3 天：接受指定配對與正式任務環節，選擇任務完成方式後開放後續活動，五點前返回。晚餐後一位新女嘉賓加入。
- 第 7 天：回憶房間意願、討論與人選確認；必要時安排不公開配對的正式談話。依本次作者確認，**第七天晚餐後**公開年齡與職業（採用每日流程，取代舊總則的第八天），仍不公開前任。
- 第 10 天：匿名禮物抽選與互選、剩餘名額補抽，未配對的一位女嘉賓與新男嘉賓約會；八點前返回後正式介紹。
- 第 13 天：雙向互選成功才約會，否則留屋；旅行搭檔另行選擇與配對，不沿用短信投票。
- 第 14 天：三男三女分組乘機、與搭檔安排行程、下午四點前集合。全員抵達並確認觀看影片後，才公開六對過去關係與事前素材。
- 第 21 天：完成兩次不能跳過的正式線上談話回答、當日短信與後訪，最後選擇重新理解過去、走向指定的新對象、或保持單身；先閱讀回顧再確認結束。

其他天安排有界線的共同生活、分工與面對面互動；具體小事由本輪種子選取，不以第三人稱披露未觀察到的私下行動。設定中的延後入場人選仍固定保存，但錄製旁白、公開名單與預告不提前列出人選或登場時程。

## 玩家作答與匿名短信

所有互動一題一題進行，不提供自由文字輸入。入住姓名由玩家自行輸入；其餘劇情回答維持選項。KKT 保留原有畫面，點下方唯讀訊息欄才開啟選項浮層；點選後直接發出自己的回答，取消不作答。採訪、匿名聊天室、短信與動作都使用同一個入口；未送出的下一題不會提前出現。

每晚先選當日在場異性，再從三組一至兩句的已寫好短信中選擇。送出時產生並固定本輪全體投票，當晚只能提交一次。先讀匿名收件（零封明確顯示「沒有嘉賓選擇您」），才解鎖 X 是否選擇你的提示；第十四天之後改為前任當晚的收件人姓名，內容仍不公開。NPC 有對其他嘉賓的偏好，不因玩家寄出短信或白天配對就強制互選。

第一天新增落座、完整到場介紹、三人分房、備菜分歧、飯桌接話及晚間單獨相處。所有出場姓名由實際在場名單產生，男嘉賓無照片。每個選擇後都有不同回應；選定對象後的對話在 X 顯示，theqoo 同集討論追加已發生的片段。

每天另有一段不同的共同生活場景，再逐題選「和誰說話」「怎樣接話」。`relationships.ts` 從已存答案重算親近、信任、表達清晰度、壓力、實際相處次數與最近相處日，不在重新開 App 時重複加分。不同選項有代價：要求立刻確認可能拉近表面距離，卻降低信任並累積壓力；保持輕鬆能留空間，卻較難讓心意清晰。私下關係數值不直接列在公開頁面。歷史片段只用截至當日的紀錄，後來的選擇不改寫過去。

第七、十四、十九天新增節目組安排的正式談話；第二十一天的必談再次確認。六種分手背景各有具體修復、只想回到過去、先守住界線的選項與不同回應。復合需有持續相處、足夠信任、確實處理原問題，並在最後談話明確同意重新交往；初始復合百分比不等於對方意願。換乘需要對同一個人的實際相處、清楚表達、後期持續靠近，並超過對方對其他嘉賓的意願；臨時改終選名字、只寄短信或反覆施壓均可能不被接受。

約會、旅行搭檔、短信及終選分別計算。第十三天互選以已累積的相處影響對方意願；夜間投票另有當日情緒、原有偏好和先前選擇。終選不再擲隨機結果：同一份存檔得到同一結果，但不同過程可以導致復合成功、復合未獲接受、換乘成功、換乘未獲接受、或主動單身。回顧使用實際選項與寄件紀錄。

X 自動置頂只在沒有正在閱讀的詳情時開啟；解鎖下一篇不會蓋掉當前推文。連續同 App 的新增段落合併到同一篇，完整讀到下一個決策點。

本作是離線故事與規則模擬，不在執行時呼叫在線模型。內容由故事資料與條件投影，不假裝能理解任意自由文字。revision 7 的問題與事件路徑已有變動，因此舊版進度會重開本輪；鎖屏與桌布仍使用作者提供的兩張合照。

## 保密與驗證

公開頁面在第十四天觀看影片以前不列前任配對；基本資訊備忘錄到第七天晚餐後才解鎖。暫時聊天室只顯示「你的約會對象的 X」，關閉後不能從原 App 繼續聯絡。第七天對未入住者的正式限制環節在獨立錄製時段完成，不把未入住者寫成已在小屋生活。

`src/story-forms/season.ts` 負責名單、合規配對、獨立投票、驗證與純文字資料投影；故事事件及進度仍使用原引擎。JSON 不含任意 HTML 或可執行匯入，原 App 的非故事功能保留。

## 網頁與離線快取更新

連線時首頁和故事 JSON 使用 Network First，故事請求包含本次建置識別碼並略過瀏覽器 HTTP 快取；離線時回退至已快取的同版資料。新版 Service Worker 接手後會將仍使用舊版的分頁導回原手機入口，不建立另一套介面，不清除 IndexedDB 存檔或桌面設定。回到分頁或恢復連線時也會檢查更新。

快取回歸測試模擬舊 Service Worker 持續返回舊首頁與故事：更新後需能自動載入最新手機、保留相容存檔、讀到同網址更新的故事，且再次離線仍能開啟。瀏覽器測試的故事路由包含版本查詢參數。

## 不含 GitHub 帳號名稱的新入口

## 換日提示與前任互動補強

KKT 收件、X 提示和其他待閱讀的正式訊息，均可從下方訊息欄繼續。第一晚完成兩題後訪後，下方直接顯示「進入第 2 天」，仍由玩家確認才換日，不自動跳過短信或採訪。

六種背景分別編寫初見時的克制、第一晚心結、介紹信、禮物，以及前期／回憶房間之後／公開之後三階段的談話。選擇自己的前任時不再使用新朋友的互動模板；熟悉感與未修復的信任分別計算。背景與先前的行動會改變回應，不把一段坦白直接當作復合。未公開前的論壇不轉述私下談話內容。

此更新保留既有 revision、事件 ID 和當前進度；舊答案仍按原選項識別，新答案另記選項序號。故事改寫可在舊進度繼續體驗，沒有新增需要重開才能到達的節點。
